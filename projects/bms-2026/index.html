Why redesign

Last year's battery pack was permanently destroyed while the car sat in storage. Before designing anything new, I needed to know why.

I traced it with current measurements on the bench. The culprit was the old BMS's isolation circuitry: a hidden 7 mA parasitic drain on the pack, 20× higher than expected.

Architecture

The fix needed to remove the cause, not just shrink it. The new BMS uses TI BQ79616 battery monitors, which talk to each other over a built-in isolated daisy chain. The separate isolators that caused the drain are gone, and the firmware shuts the monitors down whenever communication stops, so a parked car can't leave them running.

The rest of the system covers current monitoring, cell balancing, HV contactor control and CAN telemetry, across six boards in total. Power was a design goal throughout. Contactor economizers, the isoUART chain and closed-loop fan control bring the BMS to 10 W active, 5× less than the previous system, and 25 µA quiescent for the whole system, both measured on the bench.

BQ79616 driver

I wrote the driver that the segment monitoring firmware uses to run the daisy chain. It lives in the team's shared firmware platform, so any board on the car can use it. The MCU only ever talks to the BQ79600 bridge, which forwards each command up the chain and passes the replies back.

Bringing up the chain

  1. InitializeSet up the hardware CRC unit, a wake timer, the pins and the UART, without talking to the chips yet.
  2. WakeHand the UART's TX pin to a timer, which times a 2.75 ms WAKE ping on its own, in the middle of the datasheet's 2.5–3 ms window. Then give the pin back to the UART and have the bridge send a WAKE tone up the stack.
  3. Auto-addressGive the bridge address 0 and the monitors 1 to N, mark the last one as top of stack, then read the addresses back to check them.
  4. ConfigureWrite each setting to every monitor at once, then read it back from each one: cell count, communication timeout, thermistor inputs, and the thermistor reference.
  5. ReadRun a single-shot ADC round robin on every monitor and convert the cell voltages to millivolts with integer maths only.

Shutting down on lost communication

This is the step that prevents another dead pack. During configuration, every monitor is told to go into SHUTDOWN if it doesn't hear valid communication for a set time. If the MCU powers off, crashes or loses the chain, the monitors turn themselves off. Every write is verified against every device, so a monitor that missed the setting fails bring-up instead of running unprotected.

/* Stack-write one byte to every BQ79616, then stack-read it back and check every device took it */
static bq_status_t bq_stack_write_verify(uint16_t reg_addr, uint8_t value)
{
    static bq_response_frame_t frames[BQ_MAX_RESPONSE_FRAMES];
    const bq_msg_frame_t read = {
        .req      = BQ_STACK_READ,
        .reg_addr = reg_addr,
        .len      = 1U,
    };
    bq_status_t status = bq_write_byte(BQ_STACK_WRITE, 0U, reg_addr, value);

    if (status != BQ_OK) {
        return status;
    }
    status = bq_read(&read, frames, BQ_MAX_RESPONSE_FRAMES);
    if (status != BQ_OK) {
        return status;
    }
    for (uint8_t i = 0U; i < s_cfg.num_devices; i++) {
        if (frames[i].data[0] != value) {
            return BQ_ERR_VERIFY;
        }
    }

    return BQ_OK;
}

Design choices

  • Every call says why it failed. Functions return a typed status (timeout, CRC error, mismatched frame, failed verify) instead of a bare pass/fail, so a bad cable and a misconfigured chip look different in the logs.
  • Frames are checked in hardware. The STM32's CRC peripheral computes each frame's CRC-16, and every reply is checked for length, device address and register before it's used.
  • The datasheet is cited inline. Timing constants and register settings point to the datasheet section and page they came from, so the next person can check them.
  • One owner, by design. The driver uses static buffers and no lock, and its header says so: one task owns the chain, and other tasks get data from it through a queue.
