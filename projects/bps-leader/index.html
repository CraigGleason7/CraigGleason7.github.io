Overview

A solar car's battery can't be allowed to overcharge, overdischarge, overheat or carry too much current. The Battery Protection System (BPS) enforces those limits. It reads every cell's voltage and temperature and the pack current, and it controls the contactors that connect the pack to the rest of the car. If any reading leaves its safe range, or a board stops reporting, it opens the contactors and stays faulted until someone power-cycles it.

The Leader Board is the BPS's central controller. I owned it from requirements to the finished board: I designed the carrier board in KiCad and wrote all of the firmware that runs on its STM32G473. The system-on-module (SOM) that holds the microcontroller was designed by a teammate.

System

The Leader Board sits between the battery's monitoring boards and the rest of the car. Cell data arrives over the BPS's own CAN bus, and the board drives four contactors, reads three E-stop loops, and reports to the car and to the charger on separate buses.

Firmware

The firmware runs on FreeRTOS, with every task, queue, timer and event group allocated statically, so there's no heap to fragment or run out. The main design rule is priority isolation: nothing that reports data is allowed to delay the code that reacts to a fault.

Task priorities

The fault handler sits alone at the top. Below it are the tasks that check the contactors and report status, then the monitoring loops, and the CAN forwarding last.

The fault path

Any task or interrupt that sees a problem calls one function. It records which fault came first, wakes the fault handler, and yields, so the contactors open in under 7 ms from detection.

  1. A monitor detects a faultA task, or an interrupt via the FromISR variant, calls set_faultBit().
  2. The first fault is latchedInside a critical section, the first fault's ID is saved as the root cause. Later faults are still recorded, but don't overwrite it.
  3. The fault handler wakesThe fault bit is set in an event group and a binary semaphore is given. The highest-priority task preempts everything else.
  4. The pack is made safeThe contactors open, the fans go to full speed, and the strobe and fault LED turn on.
  5. It stays that wayThe handler enters a loop it never leaves. It keeps printing the root cause, but the contactors can't close again until a power cycle.
static inline void set_faultBit(uint32_t bit_index)
{
    if (fault_bits_initialized && (bit_index < NUM_FAULTS))
    {
        /* ATOMIC LATCH: Only the very first execution succeeds */
        taskENTER_CRITICAL();
        if (!system_has_faulted)
        {
            first_fault_id = bit_index; /* Save the root cause! */
            system_has_faulted = true;
        }
        taskEXIT_CRITICAL();

        EventGroupHandle_t target_group = get_target_group(bit_index);

        // determine if bit is already set. If its not, set it
        if ((target_group != NULL) && ((xEventGroupGetBits(target_group) & FAULT_BIT(bit_index % MAX_FAULT_BITS)) == 0)) {
            xEventGroupSetBits(target_group, FAULT_BIT(bit_index % MAX_FAULT_BITS));

            if (faultSemaphore != NULL) xSemaphoreGive(faultSemaphore);

            taskYIELD();
        }
    }
}

void Task_FaultHandler(void *pvParameters)
{
    while (true)
    {
        // Wait indefintiely for any fault bit to be set
        uint32_t fault_bit_index = faultBit_wait(NUM_FAULTS, portMAX_DELAY);

        LEDs_clear();
        LED_set(FAULT_LED, LED_ON);
        LED_setStrobe(LED_ON);

        emergency_open_contactors();
        set_fans_MAX();

        handle_fault(fault_bit_index);

        Fault_Loop(fault_bit_index); // WILL NEVER RETURN - while(true)
    }
}

Keeping telemetry off the fault path

CAN traffic that only needs relaying to the car never touches the monitoring tasks. The CAN receive interrupt pushes frames into a statically allocated circular queue, and a low-priority task drains it onto Car CAN. Pack current arrives faster than the car needs it, so the interrupt forwards one frame in three. A burst of CAN traffic can fill the queue, but it can't delay a fault.

Each fault also has a name, its own LED where it matters, and a detailed printout. For example, a cell overvoltage reports which module faulted, the voltage that tripped it, and its voltage now. That made bench debugging and scrutineering much faster.

Testing and CI

Most drivers and tasks have a standalone test program that runs on the board: ADC, CAN, contactors, E-stops, fans, precharge, the SHT45, the watchdog, and each monitoring task, 15 in all. A GitHub Actions workflow builds all of them with arm-none-eabi-gcc on every push and pull request, so a change that breaks any test's build can't merge.

The precharge voltage readings avoid floating point at runtime. A Python script generates lookup tables that map every raw 12-bit ADC count straight to millivolts, with the resistor divider and amplifier gain already folded in.

Hardware

The carrier board takes the car's 24 V low-voltage bus and turns it into everything the SOM needs. It also holds the contactor drivers with sense feedback, the E-stop loop, the CAN transceivers and connectors, and an ESP32 that can reflash the SOM without opening the car.

Input protection

The 24 V input goes through an LM74502 controller and an external N-channel MOSFET. It blocks reverse polarity, and it disconnects the board if the input rises above 29.03 V, set by a 200 kΩ / 9.1 kΩ divider against the controller's 1.25 V threshold. The working is written on the schematic.

24 V to 5 V buck

A TPS5405 buck converter makes the 5 V rail. I sized it for a 1.5 A load at 120 kHz. The ripple-current calculation called for at least 75 µH, so I used 100 µH. Three 10 µF output capacitors meet the ripple and ESR limit, and a 10 nF soft-start capacitor gives a 4 ms ramp. As with the input stage, the calculations sit next to the parts they chose.

Results

  • Rev B was built, tested and raced at the Formula Sun Grand Prix 2026, with zero on-track battery faults.
  • I ran the full BMS scrutineering test suite across four validation cycles before the event. The car passed electrical and BMS scrutineering on the first attempt.
